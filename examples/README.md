# Examples

Complete, runnable agents. Each one is a copy-paste starting point that demonstrates one thing, and CI runs them, so they double as executable documentation.

- [`time-bot`](time-bot/) - the minimal agent: identity, model, purpose. No triggers, so `af run` is a REPL.
- [`gh-issues-bot`](gh-issues-bot/) - the flagship: Discord to GitHub issues. A skill teaching the `gh` CLI, scoped permissions and secrets, a custom Dockerfile and a compose file, deployed with `docker compose up`.
- [`agent-zero-bot`](agent-zero-bot/) - the agent that builds agents: describe an agent in one Discord message, receive a scaffolded, validated project. It drives `af init` rather than hand-writing boilerplate.
- [`resend-bot`](resend-bot/) - an email address that does something: mail to `invoices@` arrives through the Resend transport, the agent files vendor, amount and due date into persistent memory and confirms in one line. The smallest useful shape of an inbound mailbox triggering an action.
- [`imap-bot`](imap-bot/) - a mailbox that answers itself: the agent owns `helpdesk@` over IMAP, answers the team's questions from persistent memory and learns from the mail that teaches it. A pulled transport, so no domain setup or public endpoint.
- [`rememberall-bot`](rememberall-bot/) - a Telegram memory keeper: tell it things, ask for them back later, and have it remind you at a time you name. Persistent memory plus agent-created schedules, with a Coolify deployment path in the README.
- [`whatsapp-track-bot`](whatsapp-track-bot/) - capture work from your phone: message the number "2 hours on the Acme redesign yesterday" or "remind me to invoice Acme on Friday" and it files a time entry or a todo into Looped Track. WhatsApp's Cloud API webhook plus one allowlisted host, with the API key attached server-side so it never enters model context.
- [`qbit-bot`](qbit-bot/) - a torrent butler on Telegram: paste a magnet link, ask what's downloading, get told when it finishes. A skill teaches the qBittorrent Web API; `http_request` against one allowlisted host is the whole capability.
- [`posthog-bot`](posthog-bot/) - an analytics analyst on Telegram and TTY: ask "how many signups this week?" and it writes HogQL, runs it against PostHog's query API, and answers with numbers. Server-side `http.auth` keeps the API key out of model context; schedules deliver recurring reports.
- [`github-bot`](github-bot/) - a GitHub agent for a whole account rather than one repo: the review queue, the notifications inbox, cross-repo search, CI status. Hermetic on `api.github.com`, with an opt-in CLI variant that adds `gh` and headless Claude Code — the two configs sit side by side so the trade is visible.
- [`coolify-bot`](coolify-bot/) - an operator for your Coolify instance: deploy, restart, tail logs, chase a failed build, from Telegram. A skill teaches the v1 REST API — UUID-first lookups, the asynchronous deploy lifecycle — and the API token's scope is the real blast radius.
- [`interpreter-bot`](interpreter-bot/) - the smallest useful voice agent: speak into Telegram and hear it back in another language. No permissions, no tools, no skills - the voice block is the entire capability, and the agent runs hermetic.
- [`tty-bot`](tty-bot/) - the REPL as a network surface: a WebSocket terminal endpoint with bearer auth, and the native `gemini` provider. No tools, no permissions - connect with websocat or a browser and talk.
- [`standup-bot`](standup-bot/) - an agent you talk to: it sits in the Discord standup voice channel, keeps what people said, and chases the follow-ups. Live voice plus voice notes, with the realtime model holding the conversation and the agent loop doing the work.
